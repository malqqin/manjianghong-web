## 原版依据及实现

- 原文件：`manjianghong2-original.jar`，SHA-256 `A015BC144D9579964326ADC68AEF24E7BD259500E456D059B64C91F6495F5219`。
- `l.java` 第 429 行起的 `h()`：旋风不可见时累加计数，第 434 行判断 `x >= 200 && c[0] == 1`，触发战斗前清零；原地图更新基准 80ms。因此等待约 16 秒，战斗耗时不应直接算成刷新等待。

- `y.java`、`b.java`、`i.java`：技能结算和表现按原记录组织。技能 24 含施法者最大生命 20% 的自疗；减伤变化来自 `rates[1]`，持续量来自原记录。`i.java` 的 `C()` 同时启动施法者 `s` 和目标 `r` 动画，等待两者最大时长，敌方也走此流程。
- `u.java` 及场景数据：本轮重新清点事件程序和主线关联；详细指令清单见 `output/original-parity-audit.json`，概要见 `output/parity-summary-20261118.json`。

## 美术复核

本轮未重新生图，使用项目已有 `output/imagegen/full-20261117/masters/` 和 `masters-v2/`。`scripts/restore-ai-battle-art.py` 先分析整张透明母图，再按原动画范围打包，避免武器跨格被截断。`assets/battle-art.json` 逐套记录来源类型、母图和输出哈希，`assets/battle.json` 标记运行类别。

当前 11 套 AI 重绘、1 套 AI 衍生；以下 10 套仍为原部件合成：`mon3`、`mon5`、`mon6`、`yuelinda`、`yuelei`、`niugao`、`yangzx`、`liyc`、`shenstm`、`lqsg`。战斗光效仍有原版像素动画，所以不能把“恢复已有 AI 人物”写成“所有战斗素材均已 AI 重做”。

行囊按本次要求重新设计，不是照搬问道美术；装备与药品有同类图复用。历史来源清单不再被描述为当前 PNG 与 JAR 字节一致的证明，README 和素材来源文档已同步。

另修复加载失败：运行代码和发布清单原先仍依赖已删除的 `assets/enhanced/battle-extra.json`，现已将所需额外战斗元数据合并到运行的 `assets/battle.json`，取消旧依赖。缓存升级至 `mjh-native-30`。

## 尚未达到原版一致的部分

1. 主线仍用网页 67 节点调度，缺少完整原进入/时间/坐标触发器。事件解释器尚非完整原虚拟机，部分演出、音频、平台提示指令未对应；原 Java 的联网、退出、SMS/计费入口未照搬。
2. 战斗仍是我方逐人下令后敌方行动。原速度、行动资格、反击、仇恨与异常恢复不完整，混乱逻辑简化；部分持续效果到期时机仍不同。普通失败采用休整重试，原版是 Game Over。
3. 原表基础杀气上限 100，原 Java 有扩至 300 的付费功能；网页尚未适配，因此部分耗 200 杀气绝技并非完整可达。妙手空空等相关付费特殊能力同样未完全复刻。
4. 跨图引路的部分分支出口、旧物品别名、主线赠物/失物与支线数量仍需逐段比对。旋风活动时钟目前跨地图共用，原场景生命周期没有逐条还原。
5. 仍有上述 10 套战斗角色使用原版合成；同类物品图复用。重绘本身与原版画面也存在美术差异。
6. 没有完成六章从头到尾的人工通关；没有逐个领取所有宝箱、完成每条支线或检查全部奖励。自动测试、数据清点和局部浏览器流程不能代替这一验收。
